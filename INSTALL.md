# BotGuard для Darvin CMS

Сборка от 18.11.2026. Основа: защита ProjectQ/master (`8f12d18`, `93c0940`), объединённая с темами и настройками защиты форм ms-furnitura.

## Границы переносимости

Переносится между совместимыми **Symfony/Darvin CMS** с namespace `App`, автозагрузкой сервисов `src/` и annotation routes из `src/Controller/`. Это не самостоятельный WAF и не плагин для произвольной CMS.

Проверено: PHP 7.4, Symfony 5.2, Darvin Admin 6.8, Darvin ECommerce 10.8. Установщик требует PHP >=7.3, Admin >=6.6, Admin Frontend >=6.2. Нужны Doctrine ORM/DBAL, Symfony Cache, Process, Form, Twig, PHP CLI и доступный DNS. Каталожный адаптер требует совместимую сигнатуру `Darvin\ECommerceBundle\Controller\Catalog\Action\ShowAction`.

Должна быть доступна запись в `var/bot_guard`. Атомарные лимиты и слоты используют `flock`: рассчитаны на один сервер с локальной файловой системой. Несколько серверов с разными каталогами получают отдельные лимиты. Общие численные бюджеты требуют настройки под нагрузку конкретного сайта.

## Что обновлено

- Подписанная вычислительная JS-проверка SHA-256, привязанная к IP/User-Agent, с задержкой, сроком действия и одноразовым подтверждением. Выдача проверки не создаёт файлов; старая арифметическая CAPTCHA не выдаёт допуск.
- Динамические `/filtered/` соблюдают строгое правило, включая обычный режим. Мягкая настройка действует только для подготовленных CMS-страниц вне режима «Под атакой». Deny-правила проверяются до JS-проверки.
- Google/Яндекс, включая распознаваемые служебные UA, допускаются только после обратного и прямого DNS. Подделать один UA недостаточно. Другие строки в старом белом списке сами по себе больше не дают обход: подтверждение ограничено доменами Google/Яндекса. Неизвестный робот при сбое проверки получает 503 + Retry-After; ранее подтверждённая запись переживает краткий сбой DNS.
- Атомарные счётчики с ограниченным числом файлов, отдельные бюджеты/слоты каталога для новых посетителей, допущенных браузеров и роботов. Лимиты по IP действуют в обоих режимах. Нехватка хранилища/слотов даёт 503, исчерпанный бюджет — 429; ответы не кешируются.
- Ограничена запись блокировок и подозрительных событий в БД. Сохраняются последние успешные настройки/правила на случай отказа БД/кеша.
- Ограничены POST входа в админку и запросы к `/_bot-guard/`. AJAX-проверка переходит на запрошенный URL фильтра, сохраняет его query string, не перезагружает страницу по кругу при 429/503.
- Сохранены логотип и цветовые темы защиты форм, прежние миграции и nginx-сниппеты.
- Возврат после сохранения настроек сайта и форм работает с обычными и языковыми маршрутами админки: суффикс локали не добавляется вручную. Исправлен HTTP 500 после успешной записи и при невалидной форме.

- Облегчённая проверка Uptime Kuma на главной: свежие чтения БД и проверка шаблонов, 200/503 без JS-проверки и кеша. Включается отдельно, требует доверенного IP монитора. Публичные robots/sitemap и ответы мониторинга не получают cookie допуска.
- В `extras/admin-polling/` сохранено проверенное исправление лишних фоновых запросов Darvin Admin; оно подключается вручную с учётом шаблонов сайта.

### Экран автоматической проверки

Экран проверки использует отдельный SVG-щит в цветах исходного логотипа, объёмные CSS-орбиты и необязательный наклон за курсором. Маленький медведь и название «Твердыня» остаются в шапке. Крупное вступление и подписи в анимации убраны: главный текст — «Проверяем ваш браузер», короткое пояснение и три этапа; внизу по центру — «Система защиты сайта · Безопасный доступ». Статусы соответствуют реальным этапам: вычисление, подтверждение сервером, переход. Успех не задерживается ради анимации. Учитывается `prefers-reduced-motion`; без JavaScript показана инструкция, при тайм-ауте/429/503 — ручной повтор без циклических перезагрузок.

Оформление не загружает внешние шрифты, библиотеки, аналитику или 3D-движок. Оно не использует БД и не меняет подписанную проверку, cookie и ограничения. Движения курсора нужны только для эффекта и никуда не передаются. Сборка фронта не нужна: установщик копирует `BotGuardChallengePage.php`, `challenge.css`, `challenge-scene.js`, обновлённый `challenge.js` и новый `public/assets/images/bot-guard/shield.svg`. Переносите эти файлы вместе с `BotGuardJsChallengeService.php`; запросы `/assets/bot-guard/*` должны обслуживаться как статические файлы. Версии URL CSS/JS заданы в `BotGuardChallengePage.php`.

## Установка или обновление

Сначала сохраните локальные изменения целевого сайта. Для просмотра изменений без записи:

```bash
php /path/to/botguard/bin/install.php --project-dir=/path/to/site --dry-run
```

Для применения:

```bash
php /path/to/botguard/bin/install.php --project-dir=/path/to/site
```

Перед заменой изменённых файлов установщик сохраняет их прежние версии в `site/var/bot_guard-install-backup/<date-id>/`. Повторная установка одинаковой сборки не меняет файлы и не создаёт новых резервных копий. Установщик не запускает миграции, Composer, очистку кеша или команды сайта.

Если установлен неверсионированный `dev-ecommerce-box`, установщик не может доказать его версию по lock-файлу. После отдельной проверки совместимости можно явно добавить `--allow-untested-frontend` (включая dry run). Проверка версий остальных пакетов сохраняется.

### Обязательное подключение сервисов

Из `config/snippets/services.bot_guard.yaml` перенесите определения **внутрь существующего `services:`** в `config/services.yaml`: объедините `_defaults.bind` с уже имеющимися bind, добавьте сервисы после общего ресурса `App\:`. Не создавайте второй YAML-ключ `services:` или `_defaults:`. Секции админки и переводы уже подключены через `config/packages/bot_guard.yaml`; старые ссылки на несуществующие snippets секций/переводов не нужны.

В `parameters:` файла `config/services.yaml` настройте исключения **только для API, которые уже имеют собственную авторизацию**. По умолчанию сборка не освобождает ни один API. Пример для ms-furnitura:

```yaml
parameters:
    bot_guard.integration_prefixes: ['/api/v1', '/ycp/api/v1']
    bot_guard.integration_post_paths: []
```

Префикс совпадает с самим путём и дочерними путями через `/`; `/api/v1-evil` не освобождается. `integration_post_paths` разрешает только точный путь POST вебхука. Для ProjectQ список другой: `/ycp/api`, `/market/api`, POST `/payment/webhook/yookassa` и `/delivery/webhook/cdek`. Не копируйте эти исключения на сайт, где их нет.

IndexNow, другие файлы подтверждения и нестандартные интеграции остаются адаптерами сайта. Сборка не требует параметров `index_now_*` и не содержит ключей. В ms-furnitura выдачу точного URL ключа выполняет отдельный `IndexNowKeySubscriber`.

### Каталог и AJAX

Параметры по умолчанию находятся в `config/packages/bot_guard.yaml`; переопределяйте их в `config/services.yaml`:

- `bot_guard.catalog_limits_enabled`: включение каталожных бюджетов/слотов и проверки входных параметров;
- `bot_guard.catalog_budgets`: общие запросы в минуту `{ anonymous: 120, browser: 240, crawler: 180 }`;
- `bot_guard.catalog_slots`: параллельные рендеры `{ anonymous: 2, browser: 4, crawler: 2 }`;
- `bot_guard.catalog_sorts`: реальные разрешённые значения `sort` конкретного сайта.

Для сайта без Darvin-каталога эту сборку нельзя переносить целиком: потребуются отдельные адаптеры вместо `BotGuardCatalogFilterPageRegistry` и каталожного декоратора. Оптимизации карточек, дерева каталога, фидов и проектные кеши ProjectQ в сборку не включены.

AJAX guard автоматически подключается на страницах со стандартными маркерами smart filter. Фронтенд должен помечать **все** AJAX GET каталога (включая цену и сброс последнего фильтра):

```javascript
fetch(url, { headers: { 'X-Bot-Guard-Catalog': '1' } })
```

В catch игнорируйте ошибку с `name === 'BotGuardNavigation'`: переход к выбранному фильтру уже начался. Остальные ошибки покажите пользователю, снимите прелоадер и разрешите повтор. Не вызывайте `location.reload()` при любом отказе. Сохраняйте рекламные query-параметры при формировании URL. Для нестандартных маркеров/верстки адаптируйте `BotGuardAjaxHtmlGuardAssetSubscriber`.

### Завершение установки

Для существующего BotGuard новые изменения не требуют новой миграции. На новом сайте примените включённые исторические миграции обычным процессом выпуска; не генерируйте повторные миграции на те же таблицы.

После проверки конфигурации и резервной копии БД:

```bash
php bin/console doctrine:migrations:migrate --no-interaction --env=prod
php bin/console cache:clear --env=prod
```

Выполняйте команды штатным PHP проекта. **Сохраняйте `var/bot_guard` между релизами** и не очищайте его при очистке `var/cache`: там лимиты, одноразовые подтверждения, кеш роботов и последние успешные настройки. Каталог не должен раздаваться веб-сервером. Запускайте CLI и PHP-FPM от одного пользователя. Для разных пользователей заранее создайте все каталоги с общей группой и нужными правами/umask: автоматическое создание использует 0700. Не используйте общедоступную запись.

Прогрев подтверждённых роботов (из combined access log, без изменения настроек БД):

```bash
php bin/console app:bot-guard:verify-crawlers --access-log=/path/to/access.log --limit=100 --env=prod
```

При недоступности PHP subprocess/DNS подтвердить нового робота нельзя: проверьте это до включения строгой защиты. DNS-работа ограничена по времени и количеству, отдельная команда позволяет прогревать кеш вне HTTP-запросов.

Cron для системных метрик и очистки:

```cron
* * * * * php /path/to/site/bin/console app:bot-guard:collect-metrics --env=prod >/dev/null 2>&1
17 3 * * * php /path/to/site/bin/console app:bot-guard:cleanup --env=prod >/dev/null 2>&1
```

## Apache и Nginx

Для Apache перенесите `files/apache/bot_guard_scanners.conf.snippet` в существующий `public/.htaccess` после `RewriteEngine On`, до редиректов и front controller. Фрагмент блокирует scanner URL до Symfony. Полный `.htaccess` сайта не заменяется.

Сниппеты в `files/nginx/` — примеры для ручной адаптации, установщик не меняет сервер. Блок по широкому UA может задеть обычные браузеры; список атаки не универсален. Проверка конфигурации и reload выполняются штатным процессом сервера.

`bot_guard_catalog_limits.conf.snippet` содержит общий и по-IP бюджеты каталога с отдельным списком подтверждённых IP роботов. Переименуйте nginx-зоны для каждого сайта и настройте лимиты; IP-файл должен находиться вне прав записи web-пользователя. `bot_guard_verify_limit.conf.snippet` ограничивает POST-проверки до PHP. `bot_guard_filtered_nolog.conf.snippet` уменьшает журналирование `/filtered/`, но не ограничивает запросы и не заменяет защиту. PHP-модуль сам по себе не устраняет нагрузку запуска PHP-FPM при объёмной сетевой атаке.

## Мониторинг доступности

Для Uptime Kuma можно оставить GET/HEAD главной `/`. После подключения сервисов из snippet включите проверку в `parameters:` существующего `config/services.yaml`:

```yaml
    bot_guard.uptime_enabled: true
    bot_guard.uptime_trusted_ips: ['IP_ВАШЕГО_МОНИТОРА']
    bot_guard.uptime_templates: ['@@DarvinPage/homepage.html.twig', 'layout.html.twig', 'base.html.twig']
```

Два `@` в YAML нужны для передачи буквального `@` через параметры DI. Перечень шаблонов адаптируйте к сайту. По умолчанию функция выключена, список IP пуст; адрес ms-furnitura в сборку не включён. Используется точный UA `Uptime-Kuma` или `Uptime-Kuma/<версия>`, **одного UA недостаточно**. Другие URL, методы и IP проходят обычную защиту. За reverse proxy корректно настройте Symfony trusted proxies, чтобы `getClientIp()` возвращал реальный IP монитора.

Проверка запускается до BotGuard и сессии, выполняет два свежих коротких ORM-запроса к главной с переводом `%locale%` и каталогу, проверяет маршрут главной и компиляцию указанных Twig-шаблонов. Ошибка соединения/схемы БД, отсутствие главной/заголовка, ошибка маршрута/шаблона дают **503**, подробности идут только в серверный лог. При успехе — **200 `ok`**; HEAD без тела. Ответы не кешируются, cookie не ставятся, успешный предыдущий ответ не скрывает последующий сбой БД. Нужны совместимые Darvin Page/ECommerce и маршрут `darvin_page_homepage`.

Это проверка основных зависимостей сайта: она не выполняет полный рендер главной, её виджетов и внешних сервисов. Если требуется проверять любую ошибку полного рендера, дополнительно используйте менее частую полноценную проверку страницы с обычным браузерным UA и настроенным допуском BotGuard.

`public/healthcheck.php` остаётся отдельной проверкой только web/PHP без Symfony и БД. Для контроля работоспособности приложения используйте описанную выше проверку, а не этот файл.

## Исправление фоновых запросов админки (необязательно)

Установщик не переносит `extras/` автоматически. Исправление добавляет недостающий `return` перед `reject()` в уведомлениях Darvin Admin: без адреса уведомлений/разрешения браузера прекращается `fetch` текущей страницы. При настроенных уведомлениях работа сохраняется.

1. Перенесите `extras/admin-polling/bin/patch-admin-notifications.php` в `bin/` сайта. Добавьте `@php bin/patch-admin-notifications.php` в `post-install-cmd` и `post-update-cmd` существующего `composer.json` **до** публикации assets. Скрипт проверяет исходник и обе готовые JS-сборки; повторный запуск безопасен, неизвестный upstream-код останавливает установку до записи.
2. Перенесите блок `javascripts` из `extras/admin-polling/templates/bundles/DarvinAdminBundle/base.html.twig`, сохранив собственные скрипты/блоки целевого сайта. Параметр `notifications_fix` обновляет URL кешированного JS. Не заменяйте существующий шаблон целиком без сравнения.
3. Запустите скрипт и штатную публикацию assets. Пересборка фронта не требуется. Открытые вкладки админки нужно перезагрузить.

Кеширование sitemap и его инвалидация по сущностям остаются адаптацией сайта и не включаются установщиком BotGuard.

## Приёмка на каждом сайте

1. В админке доступны настройки, правила, формы и логи; сохранение сбрасывает кеши. Темы/логотипы форм сохранены.
2. Пустой UA блокируется, поддельный Googlebot не получает обход. Настоящий подтверждённый робот получает каталог, robots/sitemap доступны.
3. Новый браузер проходит JS-проверку, повтор nonce не выдаёт допуск. Старые `_bgc=1`/`_bgcc=1` не обходят строгую защиту.
4. Фильтр, только цена, очистка, сортировка и мобильное применение сохраняют выбранный URL и рекламные параметры. При 429/503 нет циклических перезагрузок.
5. API/вебхуки доходят до собственной авторизации; соседние похожие пути не обходят BotGuard. IndexNow проверяется отдельно.
6. Под нагрузкой соблюдаются общие бюджеты/слоты, разные IP не обходят общий бюджет; исключение рендера освобождает слот. Недоступное хранилище даёт 503 + Retry-After.
